## 1. 最初に把握すること

ユーザーの最終目的は、Supermemoryの設計を参考にしたローカル記憶システムをMemoria Forgeで実用化し、品質を確認できる日本語の成果物を見られるようにすること。現在はWiki生成の連続却下を調査・修正している。システム全体も、今回のWiki生成修正も、完成とは言えない。

直近の実モデル実行では新規Wikiページは作成されなかった。ログによって、Reviewerへの入力に同一Fact IDが重複していることを特定した。これをコードで除去する回帰テストは追加済みだが、実装修正は中断され、現ファイルには入っていない。

この引き継ぎ書を作成した時点では新しいライブ実行は起動していない。過去に中断されたツール処理は、再開時に実際の状態を確認すること。ツール呼び出しを試みた事実を、変更やテストの成功と扱わない。

## 2. ユーザーの明確な指示

- 承認は計画単位。「y」「進めて」「続けて」は計画全体への承認で、後続ターンにも継続する。
- 承認済み範囲の個別ファイル編集、コマンド、テスト、通常の修正・再検証ごとに確認しない。
- コードで決定的に解決できる問題をLLMにやらせない。URL対応、ID、重複除去、構造検査などはコードが担う。
- 後で調査が必要になる場所には最初からログを仕込む。実モデル検証では入力・生応答・モデル・日時を保存する。
- 中間処理は英語でもよい。ユーザーに見せる成果物は日本語。
- 品質ゲートを弱めてページを無理に生成したり、テスト結果を歪めたりしない。
- fallbackや後方互換経路を追加しない。必要な範囲だけ修正する。
- 現DBを消して新設計にしてよいという過去の許可はあるが、旧DBにはRSS・クラスタ等の運用状態もある。現在の修正のために削除する必要はない。

ユーザーは長い診断報告だけが続き、完成したものが見えない点に不満を持っている。報告は「何が使えるようになったか」「何が未完成か」「実際に見せられる成果物」を先に示すこと。

## 6. 今回のWiki障害と修正済み事項

### 6.1 引用表現と原文一致

以前は空白・HTMLタグ・HTML実体参照の違いで `quote_not_found_in_cited_source` が続発した。

`src/atomic_facts.py` の `_normalized_source_spans()` と `canonicalize_evidence_quote()` で正規化後の引用を元ソースの厳密な部分文字列へ対応付ける。保存するevidenceは原文そのもの。意味的に違う引用は拒否する。表示・Reviewer入力は読みやすく正規化する。

この修正後の全テスト254件通過という実績がある。

### 6.2 URLをモデルに転記させていた問題

10/29の手動実行では14候補がすべて `source_url_not_allowed` で除外された。生応答を保存していなかったため、その実行でモデルが返した具体的URLは復元不能。

修正済みの抽出契約：

- `FACT_EXTRACTION_SCHEMA` は `source_url` / `source_title` を返させず、`source_id` を返させる。
- `evidence_material()` が `source-1` 等のIDを各資料に付ける。
- `extract_verified_facts()` がIDから入力資料の正規URLとタイトルをコードで引く。
- 不明IDは `source_id_not_allowed` として拒否。旧URL出力への互換fallbackはない。
- 引用は選ばれた資料本文に照合する。
- 共有処理なのでDreamingとmemory pipelineのモック応答も新契約へ変更済み。

主なテストは `tests/test_atomic_facts.py` のsource ID対応、不明ID拒否。関連31件が通過した。

### 6.3 実モデル応答ログ

`src/wiki_agent.py` の `Ollama._record_response()`、client factory、LMStudio chat経路に実装済み。

`MEMORIA_LLM_RESPONSE_LOG` を指定すると、UTF-8 JSONLへtimestamp_utc、provider、model、operation、system、prompt、response_schema、生responseを追記する。JSON内容の解析より前にモデルのcontentを保存する。Ollamaのchatとgenerate_text、LMStudioのchatが対象。

実行前に環境変数を設定する。ログはプロンプトを含むローカルデータなので、内容を無差別に外部共有しない。

## 7. 最新ライブ実行の証拠

保存済みログ：`logs/llm-response-20261030-source-id.jsonl`（48,450 bytes、2呼び出し）。Git管理外なので他マシンへの引き継ぎには別途この実ファイルも必要。

対象：`Estimating Claude Code's 5-hour window from local logs — what I learned building...`。クラスタ7135。結果は `insufficient_evidence`、新規ページなし。

ログから確認した事実：

- 抽出応答は46候補。source-1が32件、source-2が14件。
- 入力資料にはsource-1〜5があり、コードがURLに対応付けた。
- 決定的検査を通過してReviewerへ渡ったのは14行。
- その14行のFact IDは7種類で、各IDが2回ずつ現れた。
- Reviewer応答は7IDをaccepted、同じ7IDをrejectedにも返した。
- `filter_reviewed_facts()` はacceptedとrejectedの両方にあるIDを採用しないため、0件となった。

これは「Reviewerが7種類を一貫して却下した」とも「7件承認できた」とも結論できない。重複入力と矛盾した判定が観測された。重複はコードで除去してから再検証する。

同時に出た別問題：MOC更新の `UNIQUE constraint failed: moc_members.page_path`、Git index.lock権限エラー、`discord_streak` の `database is locked`。クラスターマップは更新された。Discord通常通知はno_reportでスキップ。

以前の手動実行は定期実行との重なりが疑われDB lockで失敗した。通常の手動検証にも必ず `--once --scheduled` を併用して既存のVault単位排他ロックを使う。

## 8. 直近の中断箇所（重要）

`tests/test_atomic_facts.py` に `test_extraction_deduplicates_identical_candidates` を追加済み。

同じLLM候補を2件返し、1件だけ採用・candidate-2を `duplicate_fact` と記録することを期待する。修正前のRedとして `len(facts) == 2` で失敗することを確認済み。

その後、`src/atomic_facts.py` に `verified_ids` を持たせる修正とテストを2回試みたが、ユーザーが編集承認問題のため中断した。この引き継ぎ時にファイルを再検索すると、実装側には `verified_ids` / `duplicate_fact` がなく、テスト側だけに存在した。したがって重複除去は未実装として再開する。

次に入れる最小修正案：

1. 抽出関数内で採用済みFact IDのsetを保持する。
2. 検証を通った候補でも既出IDなら追加せず、該当candidate番号をduplicate_factとして記録する。
3. 初回の有効候補だけをverifiedへ追加する。
4. Reviewer入力のID一意性と、既存の不明ID・引用拒否・保存契約をテストで確認する。

同一source URL・statement・引用をハッシュした既存Fact IDを使えばよい。意味類似による勝手な統合は不要。

## 9. 検証実績と実行上の注意

source IDと応答ログの修正後、重複除去前の確定結果：全257 passed、既存feedparser DeprecationWarning 4件。関連31 passed。変更6ファイルのruffとformat、実装4ファイルのmypyは通過。

テストファイルまで含めたmypyでは `tests/test_agent.py` の既存object型関連エラー3件が出た。通過した範囲を曖昧にしない。

pytestの既定Tempにはアクセス拒否がある。作業リポジトリ内にbasetempを置くと、Gitが親リポジトリを検出し「非リポジトリ」の2テストが環境理由で失敗する。全テストはリポジトリ外の新規専用Tempで通過した。basetempはpytestが削除・再作成するので、既存のユーザーデータがある場所を指定しない。

推奨コマンド（basetempとログ名は再開時に未使用の固有名へ変更）：

```powershell
$env:UV_CACHE_DIR = 'tasks/.uv-cache'
$env:PYTHONIOENCODING = 'utf-8'
uv run --no-sync pytest -p no:cacheprovider --basetemp="$env:TEMP\memoria-handoff-dedup-unique" -q
uv run --no-sync ruff check src/atomic_facts.py tests/test_atomic_facts.py
uv run --no-sync ruff format --check src/atomic_facts.py tests/test_atomic_facts.py
uv run --no-sync mypy src/atomic_facts.py
```

モデル検証：

```powershell
$env:UV_CACHE_DIR = 'tasks/.uv-cache'
$env:PYTHONIOENCODING = 'utf-8'
$env:MEMORIA_LLM_RESPONSE_LOG = 'logs/llm-response-dedup-unique.jsonl'
uv run --no-sync python run_agent.py --config config.json --once --scheduled
```

このコマンドは通常のライブ実行。Wiki・DB・MOC・cluster-map更新、自動Git操作、通知の可能性がある。既存の承認はこの検証1回まで含む。追加の長時間運用や大量バッチを勝手に起動しない。

JSON表示がcp932で落ちた過去があるためUTF-8設定を忘れない。CLIが非ゼロ終了しても、それだけで生成失敗と判断せず、DBのrunsとファイル更新・ログを照合する。
