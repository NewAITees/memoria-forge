# GPUは2つの役割を持ち、モデルを保持するのはそのうちの1つ

## 結論

GPUの性能において、モデルを保持するためのVRAMは決定的な要因であり、モデルのロードと実行において中心的な役割を果たす。特に、大規模言語モデル（LLM）ではVRAMの容量がモデルのサイズに直接影響を与え、モデルが収まらない場合、CPUへのオフロードが発生し、性能低下や遅延を引き起こす。また、1つのGPUは一度に1つのモデルのみを保持できるため、複数モデルの実行にはスケジューリングやシャーディング技術が不可欠である。

## テーマ概要

GPUは、計算コアとVRAMの2つの主要な要素から成り立っているが、モデルのロードと実行においてはVRAMが中心的な役割を果たす。このテーマでは、GPUの性能を左右する2つの側面のうち、モデルを保持するためのVRAMの重要性が強調されている。近年、大規模言語モデル（LLM）の利用が増加し、それに伴ってGPUのVRAM容量がモデルの実行に直結するという認識が広がっている。特に、モデルのサイズがVRAMの制約を越えると、CPUへのオフロードが必要となり、性能低下や遅延が生じるため、VRAMの確保が課題となっている。また、複数のモデルを同時に実行する際には、GPUのVRAMがモデルを1つずつ保持できる制限があるため、スケジューリングやシャーディング技術が注目されている。このような背景から、GPUのVRAMがモデルの実行に与える影響についての議論が活発化しており、本テーマはその中核を担っている。

## 共通して確認できる点

GPUは、計算コアとVRAMの2つの主要な要素から構成されている。モデルはVRAMに保持され、計算コアがそのデータを処理する。例えば、80億パラメータのモデルは約16GBのVRAMを必要とし、GPUのVRAM容量がモデルのロードに直接影響を与える。一方で、計算コア自体は記憶領域を持たず、連続的なデータの読み込みが求められるため、モデルの計算はVRAMを介して行われる。このため、GPUの性能はVRAMのサイズ、計算コアの数、およびデータ転送速度に大きく依存する。

記事1では、VRAMがローカルLLMを実行する上で最も重要な要素であると強調されており、Llama 3.1 8Bモデルの場合、Q4_K_Mの量子化形式では約6GBのVRAMが必要とされている。また、モデルの文脈長がVRAM使用量に影響を与えることも指摘されており、4K文脈では約0.3GB、32Kでは約2.5GB、128Kでは約10GBの追加VRAMが必要になる。さらに、モデルがVRAMに収まらない場合、CPUへのオフロードが行われるが、これは低遅延タスクには有効だが、長いドキュメントの処理には不向きである。

記事5では、1つのGPUは同時に1つのモデルのみを保持できるという制限があることが述べられており、複数のジョブを実行するにはスケジューリングが必要である。これは、GPUのVRAMがモデルのロードに直接関与するための制約として理解される。また、記事2では、TPU v5eチップを用いることで、Gemma-4-E2B-itモデルを高速に処理でき、1つのチップで複数の「ライトエージェント」をサポートできるとされている。これにより、GPUやTPUの選択がモデルの実行効率に大きく影響することが示されている。

## 記事ごとの差分・視点の違い

記事「VRAM Requirements for Local LLMs: The Complete Guide (2026)」は、GPUのVRAMがローカルLLMの実行において最も重要な要素であると強調し、具体的なVRAM要件やモデルのサイズ、量子化形式の影響を解説している。特に、Llama 3.1 8BやLlama 3 70BなどのモデルのVRAM使用量を示し、複数GPUを用いたテンソル並列処理の可能性も触れている。  
記事「Self-hosting a lite agent backend on one TPU: Gemma4E2B+vLLM...」は、TPUを用いたモデルの実行環境を検証し、TPU v5eチップの性能やコスト、スケジューリング方法を詳細に説明している。この記事では、GPUではなくTPUを用いた実行環境の設計が焦点であり、モデルのスケーラビリティやコスト効率が主な論点となっている。  
記事「Graphics processing unit - Wikipedia」は、GPUの一般的な役割とその進化を説明し、AI処理やモデルトレーニングにおけるGPUの利用を背景にしている。この記事は技術的な背景を提供し、GPUがAI分野でどのように活用されているかを広く解説している。  
記事「NotebookLMShortVideoOverviews: Language Support」は、GoogleのNotebookLM製品における短い動画オーバービュー機能の言語サポート状況を解説し、英語のみの制限を明記している。この記事は製品の機能制限とその影響を分析しており、ビジネス利用における言語選択の重要性を指摘している。  
記事「Scheduling every job on a GPU that can only hold one model」は、GPUが一度に1つのモデルしか保持できないという制限を前提に、ジョブのスケジューリング方法を考察している。この記事では、GPUの使用効率やリソース管理の工夫が主な論点であり、実際の運用環境における課題を具体的に提示している。

## 深掘り調査で得られた知見

GPUは、計算コアとVRAMの2つの主要な要素から成り立つが、モデルのロードと実行においてはVRAMが中心的な役割を果たす。例えば、Llama 3.1 8BモデルはQ4_K_Mの量子化形式で約6GBのVRAMを必要とし、Llama 3 70BモデルはQ4形式で40〜43GBのVRAMが必要となる。これは、モデルが完全にVRAMにロードされる必要があるためであり、計算コアはそのデータを処理するが、記憶領域を持たず、連続的なデータ読み込みに依存している。そのため、モデルの計算はVRAMを介して行われる。

また、GPUの性能はVRAMのサイズ、計算コアの数、およびデータ転送速度に大きく依存する。たとえば、1つのTPU v5eチップ（16GB HBM）は、google/gemma-4-E2B-itモデルをvLLMで実行し、1,496 output tokens/secの速度で処理可能である。これは、GPUのVRAMがモデルを保持するための限界であり、複数のモデルを同時にロードすることはできない。そのため、モデルのスケジューリングや、複数のタスクをGPU上で効率的に実行するためには、VRAMの容量を考慮した設計が必要となる。

さらに、Apple Silicon（M1/M2/M3/M4）では統合メモリが使用され、Ollamaはその70%をVRAMとして利用する。モデルがVRAMに収まらない場合、CPUへのオフロードが行われるが、これは低遅延タスクには有効だが、長文の処理には不向きである。このような現状から、GPUのVRAMはモデルの実行において不可欠であり、計算コアの性能に比べて、より直接的な影響を及ぼす。

## 不確実な点・追加確認が必要な点

GPUは計算コアとVRAMの2つの主要なコンポーネントから構成されているが、どの記事も明確に「モデルがVRAMに保存される」という点を共有している。しかし、記事1と記事5では、VRAMがモデルのロードに直接関与する一方で、記事2や記事3では、TPUやGPUの計算コアがモデルの実行に直接関与しているとされている。また、記事5では「GPUは一度に1つのモデルしか保持できない」という点が強調されており、これはVRAMの制約によるものと考えられるが、他の記事ではそのような制限が明示されていない。さらに、記事1では「モデルがVRAMに保存され、計算コアがそのデータを処理する」という流れが説明されているが、記事2ではTPUのHBM（高帯域幅メモリ）がモデルを保持しており、計算コア（TPUの計算ユニット）が処理を行うとされている。このように、VRAMと計算コアの役割分担については、記事によって異なる解釈が示されている。また、記事3のWikipediaの説明では、GPUはグラフィックス処理だけでなく、AIのトレーニングにも利用されているとされているが、どの記事も「GPUがモデルを保持する」という点を明確に述べているわけではない。そのため、モデルが保持されるのはVRAMなのか、計算コアなのか、あるいはその他の要素なのかについては、記事間で一貫性が欠けている。
