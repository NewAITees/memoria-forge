# IDドキュメント写真の安全なアップロード方法

## 結論

IDドキュメントの写真を安全にアップロードするためには、最小限のデータを保持し、スケジュールされた削除をデータパスに組み込むことが不可欠であり、IDデータは他のメディアタイプと分離して管理する必要がある。短命の署名付きURLやプライベートなオブジェクトストレージの利用、削除期限の違反を検出するアラート機能の導入は、セキュリティを高めるための基本的な設計原則である。また、認証プロセスは単なるログインフォームではなく、セキュリティサブシステムとして設計され、パスワードハッシュ化や認証フローの厳密な管理が求められる。

## テーマ概要

Identity Document Photos Explained: A Secure API Approach for Uploads は、ユーザーが身分証明書の写真をアップロードする際のセキュリティを確保するためのAPI設計方法についての話題です。このテーマは、個人情報の漏洩やデータの不適切な保持を防ぐため、最小限のデータを保持し、スケジュールされた削除をデータパスに組み込むことが重要であると強調しています。特に、アップロードされた写真は、認証処理中にのみ保持され、その後は即座に削除されるべきです。また、短命の署名付きURLやプライベートなオブジェクトストレージの利用が推奨されており、削除期限の違反を検出するアラート機能も重要な要素として挙げられています。このような設計は、金融テックやセキュリティに高い要求がある分野で特に注目されており、データのライフサイクル管理とセキュリティの確保が求められる状況において、重要性が高まっています。

## 共通して確認できる点

複数の記事で共通して確認できた事実として、IDドキュメントの写真のアップロードにおいては、セキュアなAPIアプローチが推奨されている。具体的には、最小限のデータのみを処理し、IDチェックの期間内にのみオリジナルの写真を保持するべきである。また、スケジュールされた削除をデータパスの一部として実装し、削除期限を過ぎた写真が依然として取得可能であることを検知するアラートが求められている。さらに、IDデータは他のメディアタイプと分離して管理すべきであり、短命の承認されたアクセスメカニズムやプライベートなオブジェクトストレージの利用が推奨されている。これらの設計は、セキュリティを高め、誤ってアクセスされた場合でも敏感な情報が漏洩しないようにするための重要な要素である。

## 深掘り調査で得られた知見

深掘り調査では、IDドキュメントの写真を安全にアップロードするためのAPI設計に関する多角的な知見が得られた。まず、データの最小限の保持とスケジュールベースの削除が強調されている。これは、IDドキュメントが保持すべき期限を明確に設定し、その期限を過ぎたデータが依然としてアクセス可能である場合、システムがその状態を特定し、適切なアラートを出す必要があることを示している。例えば、ある記事では、26時間以上経過した未削除のオリジナルデータが存在する場合、その状況を明示的に通知するべきだと述べている。

また、ID情報は他のメディアタイプと分離して管理する必要があることが確認されている。これは、認証が失敗した場合や削除ジョブが停止した場合に、敏感な情報が誤って露出するリスクを減らすための設計である。さらに、短命の署名付きURLやプライベートなオブジェクトストレージの使用が推奨されており、これによりIDデータのセキュリティが強化される。

一方、ACAIプラットフォームでは、ファイルストレージが次の主要サブシステムとして導入される予定であり、メタデータはPostgreSQLに、大容量のバイナリデータはオブジェクトストレージに分離して保存する必要がある。この設計はスケーラビリティ、パフォーマンス、ライフサイクル管理、セキュリティを向上させる。プライベートなファイルは認証後にのみアクセス可能とし、短命の承認されたアクセスメカニズムを発行することが求められている。

さらに、認証プロセスは単なるログインフォームではなく、完全なセキュリティサブシステムとして設計されるべきである。これには、アカウント登録、パスワード保護、安全なパスワードハッシュ化（例：Argon2id）が含まれる。このような設計により、IDドキュメントの写真のアップロードと管理がより安全で信頼性のあるものとなる。
