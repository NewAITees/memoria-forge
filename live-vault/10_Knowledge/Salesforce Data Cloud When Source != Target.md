# Salesforce Data Cloud: ソースとターゲットが異なる場合の導入課題

## 結論

Salesforce Data Cloudの導入において、ソース環境とターゲット環境が表面的に一致していても、デプロイが失敗するケースがあることが確認された。これは、データスペース、コネクター、データストリーム、DLO、DMO、マッピング、アイデンティティ解決、データグラフ、関係性などの相互に関連するコンポーネントが存在するためであり、1つの領域での違いが他の領域に影響を及ぼす可能性がある。そのため、ソースとターゲット環境を手動で比較し、導入の検証チェックリストを作成して各コンポーネントの依存関係を確認することが重要である。

## テーマ概要

Salesforce Data Cloudは、企業が多様なデータソースから統合データを取得し、リアルタイムで分析・活用できるプラットフォームとして注目されている。その導入において、ソース環境とターゲット環境が形式的に同じであっても、デプロイが失敗するケースが報告されている。これは、データスペース、コネクター、データストリーム、データレーキオブジェクト（DLO）、データモデルオブジェクト（DMO）、データマッピング、アイデンティティ解決、データグラフ、関係性などの相互に関連するコンポーネントが含まれているためである。これらのコンポーネントは孤立していないため、1つの領域での違いが他の領域で問題を引き起こす可能性がある。そのため、ソースとターゲット環境を手動で比較し、導入の検証チェックリストを作成して各コンポーネントの依存関係と関係性を確認することが推奨されている。このテーマは、クラウド環境でのデータ統合とデプロイの複雑性を浮き彫りにし、企業がデータ活用を進める上での課題を明らかにする重要な話題として注目されている。

## 共通して確認できる点

Salesforce Data Cloudの導入において、ソースとターゲット環境が表面的に一致しているにもかかわらず、デプロイが失敗することがある。これは、データスペース、コネクター、データストリーム、データレーキオブジェクト（DLO）、データモデルオブジェクト（DMO）、データマッピング、アイデンティティ解決、データグラフ、関係性などの相互に関連するコンポーネントが含まれているためである。これらのコンポーネントは孤立していないため、1つの領域での違いが他の領域で問題を引き起こす可能性がある。例えば、コネクターからデータストリーム、DLO、DMO、マッピング、関係性、アイデンティティ解決、データグラフへの依存関係が正しく構成されているかを確認する必要がある。導入の失敗はデプロイエラーによって示されることはあっても、そのエラーが本質的な原因であるとは限らない。そのため、デプロイエラーに過度に注力するのではなく、ソースとターゲット環境を手動で比較することが重要である。また、導入の検証チェックリストを作成し、各コンポーネントの依存関係と関係性を確認することが推奨される。
