# VS Code拡張機能とTypeScriptコアの分離設計

## 結論

Aqiron Securityのアーキテクチャ変更により、VS Code拡張機能とTypeScriptコアプロセスの境界が明確になり、セキュリティサービスがVS Codeに依存しなくなる設計が実現された。この分離は、拡張機能の責任範囲を限定し、コアロジックを分離することで、よりスケーラブルで保守性の高いアーキテクチャを実現するための重要な設計選択である。また、eBPFを用いたランサムウェア検出ツールの開発は、ファイル操作の行動をもとに異常を検出する手法により、ランサムウェアの検出に有効である。

## テーマ概要

VS Code拡張機能とTypeScriptコアアーキテクチャの分離というテーマは、Aqiron Securityというオープンソースのアプリケーションセキュリティプロジェクトにおけるアーキテクチャ設計の変更を背景としています。このプロジェクトでは、セキュリティロジックを拡張機能内で実行するのではなく、別個のNode.jsプロセスでTypeScriptコアを実行する設計に移行しました。この変更は、拡張機能がクライアントとして動作し、コアプロセスがスキャン、分析、相関、レポート生成などの責任を担うことで、セキュリティサービスがVS Codeに依存しなくなるように設計されています。このようなアーキテクチャの分離は、拡張機能とコアプロセスの境界を明確にし、セキュリティ機能の柔軟性と信頼性を高めるための重要な設計選択です。また、このテーマは、拡張機能の責任範囲を限定し、コアロジックを分離することで、よりスケーラブルで保守性の高いアーキテクチャを実現するための参考となるため、現在注目されています。

## 深掘り調査で得られた知見

Aqiron Securityは、VS Code拡張機能として提供されているオープンソースのアプリケーションセキュリティプロジェクトであり、そのアーキテクチャの再設計を通じて、拡張機能とTypeScriptコアプロセスの境界を明確にしています。初期にはセキュリティロジックを拡張機能内で実行していましたが、スキャンオーケストレーションや検出結果の正規化、相関、AI操作などの機能を追加するにつれて、アーキテクチャの再設計が必要となりました。結果として、拡張機能はクライアントとして動作し、別個のNode.jsプロセスでTypeScriptコアを実行する設計が採用されました。このアーキテクチャでは、拡張機能は外部ツールの起動、スキャナーオーケストレーション、検出結果の正規化、レポート生成などの責任を担い、コアプロセスはスキャン、分析、相関、レポート生成、AI操作などの責任を担います。現在のアーキテクチャはローカルファーストで、拡張機能がコアプロセスをローカルで起動し、標準入出力で通信しています。CLIツールはリポジトリ内で提供されており、コアプロセスを呼び出すことができます。AI機能はオプションであり、ユーザーが選択したAIプロバイダーを使用します。拡張機能はFlutterプロジェクトに特化しており、その他のファイルタイプをサポートしていますが、完全なワークスペースサポートはまだありません。この設計により、拡張機能とコアプロセスの境界が明確になり、セキュリティサービスがVS Codeに依存しなくなるように設計されています。

また、eBPF（extended Berkeley Packet Filter）を用いたランサムウェア検出ツールとして、talus-process-monitorが開発されています。このツールは、Linuxカーネルレベルでexecve、openatなどのシステムコールを監視し、ファイル操作の異常なパターンを検出します。ランサムウェアは通常、短時間で大量のファイルを開き、書き換え、拡張子を変更する傾向があります。この振る舞いをリアルタイムで検知することで、暗号化前の段階で対応が可能になります。ユーザー空間ではRustが使用され、eBPFプログラムはlibbpf/CとCO-RE技術で実装されています。perfバッファをCPUごとに割り当てることで、並列処理時のイベント衝突を回避し、データの正確な収集が可能になります。誤検知を減らすため、拡張子変更の頻度、読み書き密度、影響範囲などのヒューリスティックを分析し、スコアリングによる検出精度を向上させています。開発者によると、一般的な開発活動（cargo buildなど）でも高頻度のファイル操作が発生するため、スコアリングの精度が重要です。talus-process-monitorはMITライセンスで公開され、商用利用可能なeBPFベースのランサムウェア検出ツールとして提供されており、検出に成功した場合、SIGKILLを発行し、ランサムウェアプロセスを即座に終了させることができます。このツールは、シグネチャではなく、ファイル操作の「行動」をもとに異常を検出する手法により、ランサムウェアの検出に有効です。

さらに、eBPFのverifierは、プログラムの安全性を確保するために、無限ループを許可せず、明示的な境界を持つループ（bounded loops）のみを許可しています。これは、verifierがプログラムの実行中に不確実な動作を防ぐための設計です。CO-RE（Compile Once - Run Everywhere）は、BTF（Binary Toolkit Framework）を用いて場所のオフセットを動的に調整しますが、これは各カーネルバージョンごとに変化するため、ポータビリティを達成するためには各カーネルでのテストが必要です。eBPFのverifierは、複雑なループや分岐を処理する際、最大100万の状態を処理できるが、それ以上の複雑さはエラーとして扱われます。また、mapのアクセスパターンは、verifierによって制限され、特定のパターン（例：mapの全要素のスキャン）はロード時に拒否されます。これらの制限は、eBPFのverifierがプログラムの安全性を保証するための設計制約であり、開発者はこれらの制限を理解し、適切にプログラムを構築する必要があります。
