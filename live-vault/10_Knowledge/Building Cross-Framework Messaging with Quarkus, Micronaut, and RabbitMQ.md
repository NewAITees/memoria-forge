# JVMアプリケーション間のクロスフレームワークメッセージング

## 結論

QuarkusとMicronautを用いたJVMアプリケーション間でのRabbitMQによるクロスフレームワーク通信は、共通のメッセージコントラクトを確立し、非同期メッセージングを実現するための有効な手法である。このアプローチでは、Gradleプロジェクトcommonを介してモデルを共有し、RabbitMQをメッセージブローカーとして利用することで、異なるフレームワーク間での信頼性の高い通信が可能となる。また、QuarkusのRabbitMQ連携はSmallRye Reactive Messaging RabbitMQ Connectorを用いており、ネイティブ実行可能ファイルの構築も可能である。

## テーマ概要

JVMエコシステム内において、Quarkus、Micronaut、Spring Bootなどのフレームワークを用いたアプリケーション間での通信が求められるようになってきた。特に、マイクロサービスアーキテクチャやクラウドネイティブ開発の普及により、異なるフレームワークで構築されたサービス間での連携が必須となっており、これに応じてRabbitMQなどのメッセージキューを活用したクロスフレームワークの非同期通信が注目されている。RabbitMQは、メッセージの送受信を仲介し、アプリケーション間での信頼性の高い通信を実現するため、多様なフレームワークとの連携が可能である。このテーマでは、QuarkusとMicronautを用いたRabbitMQによるクロスフレームワーク通信の実装方法が示されており、JVMアプリケーション間での統一されたメッセージコントラクトを確立するための技術的アプローチが解説されている。また、QuarkusのRabbitMQ連携はプレビュー段階であり、今後の進化やエコシステムの拡大が期待されている。

## 共通して確認できる点

Quarkus、Micronaut、およびRabbitMQを用いたクロスフレームワーク間のメッセージングは、JVMアプリケーション間での非同期通信を実現するための手法として複数の記事で取り上げられている。RabbitMQは、これらのフレームワーク間でのメッセージ送受信を仲介するメッセージブローカーとして機能し、アプリケーション間での連携を可能にする。QuarkusアプリケーションはSmallRye Reactive Messaging RabbitMQ Connectorを使用してRabbitMQにメッセージを送信し、Micronautアプリケーションはそのメッセージを受信して処理する。また、共通のメッセージコントラクトを確立するため、Gradleプロジェクトcommonが作成され、LeaveRequestモデルが共有される。Micronautでは、@Introspectedと@Serdeableアノテーションを用いて、メッセージのシリアライズとデシリアライズを効率化する。一方、QuarkusのRabbitMQ連携はプレビュー段階であり、バックワードコンパチビリティやエコシステムの存在は保証されていない。ただし、Quarkus CLIやMandrel、GraalVMなどのツールを用いることで、ネイティブ実行可能ファイルの構築が可能である。また、MicronautはJVM上で軽量でモジュール化されたアプリケーションのためのフレームワークであり、依存関係の注入（DI）をコンパイル時に実行することで起動時間を短縮し、メモリ使用量を削減している。MicronautはJava、Groovy、Kotlinをサポートし、マイクロサービスの開発を速やかかつ容易にする。さらに、Micronaut Gradleプラグインは、Micronaut 4.xとGradle 8+で動作し、Micronaut 5.0.2をデフォルトとしており、アプリケーションの構築を容易にする。Spring Bootは、Javaベースのフレームワークで、簡潔な構成と自動設定により、WebアプリケーションやREST API、マイクロサービスの開発を簡素化している。Spring Bootは2013年にリリースされ、クラウド環境でのデプロイや外部サーバー不要な独立実行が可能であり、生産環境での利用に適している。

## 深掘り調査で得られた知見

QuarkusとMicronautを用いたJVMアプリケーション間でのRabbitMQによるクロスフレームワーク通信は、非同期メッセージングの実現に有効であることが確認された。この手法では、共通のメッセージコントラクトを確立するために、Gradleプロジェクトcommonが作成され、LeaveRequestモデルが共有される。QuarkusアプリケーションはSmallRye Reactive Messaging RabbitMQ Connectorを使用してRabbitMQにメッセージを送信し、Micronautアプリケーションはそのメッセージを受信して処理する。RabbitMQはメッセージの送受信を処理し、アプリケーション間での非同期通信を可能にする。QuarkusのRabbitMQ連携は、Reactive Messaging RabbitMQ Connectorを使用しており、Quarkusプロジェクトに追加する必要がある。また、QuarkusのRabbitMQガイドでは、技術がプレビュー段階であり、バックワードコンパチビリティやエコシステムの存在は保証されていないと述べられている。ガイドでは、Quarkus CLIやMandrel、GraalVMなどのツールが推奨されており、ネイティブ実行可能ファイルの構築が可能である。

Java 25（JEP 512）で導入されたコンパクトソースファイルは、Javaプログラムを起動可能な形で記述できるようにする機能であり、明示的にクラスやpublic static void mainメソッドを宣言せずに記述できる。これは、Micronautアプリケーションの起動処理を簡略化するための機能である。従来の方法ではmainメソッドを含むApplication.javaファイルが必要だったが、コンパクトソースファイルによりその手順を削減できる。コンパクトソースファイルはパッケージ宣言を含まないため、Gradleの構成ファイルで完全なクラス名を指定する必要がなくなり、ファイル名とmainClassが一致する必要がある。MicronautのGradleプラグインは、Micronaut 4.xとGradle 8+で動作し、Micronaut 5.0.2をデフォルトとしており、Micronautアプリケーションの構築を容易にする。

MicronautはJVM上で軽量でモジュール化されたアプリケーションのためのフレームワークであり、依存関係の注入（DI）をコンパイル時に実行することで、起動時間を短縮し、メモリ使用量を削減している。MicronautはJava、Groovy、Kotlinのサポートを提供し、マイクロサービスの開発を速やかかつ容易にする。また、サービスの検出（service discovery）や分散トレース（distributed tracing）などの機能をサポートし、クラウドネイティブアプリケーションの開発に適している。Micronaut CLIはSDKMANなどを通じてインストール可能で、プロジェクトのセットアップを容易にする。MicronautはGraalVMをサポートし、ネイティブ実行可能なバイナリを生成することができ、起動時間とメモリ使用量の削減が可能である。

Spring Bootは、Springフレームワーク上で構築され、アプリケーションの開発を簡素化するJavaフレームワークである。冗長なコードや構成の削減により、開発を効率化し、生産環境での使用に適した機能を提供している。2013年にリリースされ、ウェブアプリケーション、REST API、マイクロサービスの開発に広く使用されている。Spring BootはSpring Cloudとの統合も可能であり、マイクロサービスアーキテクチャの実装に適している。フレームワークはクラスパスの依存関係に基づいてアプリケーションを自動的に構成し、XML構成の必要性を排除している。Spring Bootアプリケーションはクラウド環境にデプロイされ、外部サーバーなしで独立して実行可能である。健康チェック、メトリクス、外部構成などの生産環境向け機能を提供し、実世界での使用に適している。
