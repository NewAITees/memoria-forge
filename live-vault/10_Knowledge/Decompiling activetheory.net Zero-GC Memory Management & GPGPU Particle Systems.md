# activetheory.netのゼロGCとGPGPU粒子システム解明

## 結論

activetheory.netのゼロGCメモリ管理とGPGPUを活用した粒子システムは、JavaScriptヒープのフラグメンテーションと瞬時オブジェクト割当を排除することで、V8エンジンでの持続的な高フレームレートを実現しており、WebGLやWebGPUを用いたリアルタイム視覚表現のパフォーマンス最適化において重要な技術として位置付けられている。一方、vizcrushの開発過程では、WASMとJSのパフォーマンス比較がエンジンやバージョンによって大きく異なることが明確に示され、設計決定がベンチマーク結果に基づく必要性が強調されている。また、Rustを用いたWebGPU実装では、複数のプラットフォームで動作可能なwgpuライブラリの設計が示され、安全かつ柔軟なグラフィックスAPIとしての可能性が確認されている。

## テーマ概要

activetheory.netのゼロGCメモリ管理とGPGPUを活用したパーティクルシステムの実装は、高パフォーマンスなWebグラフィックスアプリケーションの設計において注目されている。この技術は、JavaScriptヒープのフラグメンテーションと瞬間的なオブジェクト割当を排除することで、V8エンジンでの持続的なフレームレートを維持する。特に、AntimatterというGPGPUサブシステムがオフスクリーンのEulerianグリッドを用いて流体のシミュレーションを行い、OpenGL ESの浮動小数点テクスチャ(OES_texture_float)をピンポン双方向バッファリングで利用し、GPUフラグメントシェーダーで粒子の統合を実現している。このようなアプローチは、WebGLやWebGPUを用いたリアルタイムな視覚表現において、メモリ管理とパフォーマンスの最適化を追求する技術として、現在のWeb開発において重要な位置を占めている。また、同様の技術的挑戦を乗り越えたプロジェクトとして、vizcrushというRustで実装されたWebビジュアライゼーションライブラリも注目されており、WASMとJSのパフォーマンス比較を通じた設計決定が行われている。

## 共通して確認できる点

activetheory.netは、JavaScriptヒープのフラグメンテーションと瞬時オブジェクト割当を排除したゼロGCメモリ管理を採用している。V8エンジンでは、静的なスクラッチパッドプール(_v1, _v2)を使用し、メモリの再割当を回避し、フラットなヒープのラインを維持している。GPGPUを活用したオフスクリーン浮動小数点パイプラインが採用され、粒子システムのシミュレーションが行われている。AntimatterというGPGPUサブシステムが、オフスクリーンのEulerianグリッドを用いて流体の流れをシミュレートしている。OpenGL ESの浮動小数点テクスチャ(OES_texture_float)がピンポン双方向バッファリングによって使用され、GPUフラグメントシェーダーで粒子の統合が行われている。48kHzのスタジオ空間化グラフが使用され、16-bin AnalyserNode FFT分析、一時的な活動制限、心理音響論的対数フィルタスイング(logLerp)が行われている。Headless Chrome DevTools Protocolによる600連続フレームのトレースが行われ、V8ヒープのフラットラインが検証されている。  

また、VizcrushはRustで書かれており、WebAssemblyにコンパイルされ、純粋なJavaScriptコアを備えたデータ処理ライブラリである。ダウンサンプリング、ビニング、空間インデックス、ストリーミングスケッチなどの機能を提供し、D3、Three.js、WebGPUなどのレンダリングライブラリと連携している。このプロジェクトでは、初期のパフォーマンス主張がベンチマーク結果に基づき再考され、3つの主張が撤回された。WASMのパフォーマンスは実行環境やバージョンにより変化し、 Chromium 148ではWASMがJavaScriptコアより4倍速だったが、Chromium 149ではJavaScriptコアがWASMより3.36倍速となった。FirefoxやSafariではJavaScriptコアがWASMと同等または速い。  

さらに、Rustを用いてWebGPUを実装する技術も紹介されており、wgpuはWebGPU標準に基づき、Vulkan、Metal、D3D12、OpenGL、WebGPU、WebGL2など複数のプラットフォームで動作可能である。wgpuはFirefox、Servo、Denoなどのプロジェクトで使用され、安全なグラフィックスAPIとして設計されている。Rustのエコシステムを活用したWebGPUの抽象化実装が行われており、ドキュメンテーションやサンプルコードが提供されている。

## 深掘り調査で得られた知見

activetheory.netのゼロGCメモリ管理は、JavaScriptヒープのフラグメンテーションと瞬間的なオブジェクト割当を排除することで、V8エンジンでの高パフォーマンスを実現している。この実行時環境では、静的なスクラッチパッドプール(_v1, _v2)が使用され、メモリの再割当を回避し、フラットなヒープのラインを維持している。GPGPUを活用したオフスクリーンの浮動小数点パイプラインが採用されており、粒子システムのシミュレーションが行われている。AntimatterというGPGPUサブシステムが、オフスクリーンのEulerianグリッドを用いて流体の流れをシミュレートしている。OpenGL ESの浮動小数点テクスチャ(OES_texture_float)が、ピンポン双方向バッファリングによって使用され、GPUフラグメントシェーダーで粒子の統合が行われている。48kHzのスタジオ空間化グラフが使用され、16-bin AnalyserNode FFT分析、一時的な活動制限、心理音響論的対数フィルタスイング(logLerp)が行われている。Headless Chrome DevTools Protocolによる600連続フレームのトレースが行われ、V8ヒープのフラットラインが検証されている。  

一方、vizcrushはRustで書かれたデータ処理ライブラリで、WebAssemblyにコンパイルされ、JavaScriptコアをバックアップとして提供している。このプロジェクトでは、ベンチマーク結果に基づき、当初のパフォーマンス主張の一部が撤回された。特に、JavaScriptコアが最も人気のあるnpmダウンサンプリングパッケージを32倍速く処理するという主張は、ベンチマーク結果をもとに撤回された。WASMによるパフォーマンス向上の主張も、ベンチマーク結果が示すところを考慮すると撤回された。WASMのパフォーマンスは、使用するエンジンやバージョンによって大きく異なるため、Chromium 148ではWASMがJavaScriptコアを4倍速く処理していたが、Chromium 149ではJavaScriptコアが3.36倍速く処理されるようになった。FirefoxやSafariではJavaScriptコアがWASMを上回る場合もある。また、WebGPU経由でのbin2d処理は転送コストのため、WASMよりも遅いため、vizcrushでは自動選択しない。これらの測定結果や制限、拒否された最適化は、ADR（Architecture Decision Records）として記録されている。  

さらに、WebGPUをRustで実装するプロジェクトとして、wgpuというライブラリが挙げられる。wgpuはWebGPU標準に基づいており、Vulkan、Metal、D3D12、OpenGL、WebGPU、WebGL2など複数のプラットフォームで動作可能。Firefox、Servo、Denoなどのプロジェクトで利用されており、安全なグラフィックスAPIとして設計されている。Rustのエコシステムを活用してWebGPUの抽象化を実現するための実装が行われており、ドキュメンテーションやサンプルコードが提供されている。ただし、wgpuのMSRV（Minimum Supported Rust Version）に関する情報が異なるため、注意が必要である。また、WebGPUの実装はブラウザによって異なり、一部のブラウザでは有効化が必要な場合がある。
