# GitHubテンプレートリポジトリのコピーとOpenAPI互換性リスク

## 深掘り調査で得られた知見

GitHubのテンプレートリポジトリは、コピーされたリポジトリと共有するコミットが一切ないため、テンプレートの変更を子リポジトリに反映させることが困難である。テンプレートリポジトリの変更を子リポジトリに引き継ぐには、`--allow-unrelated-histories`オプションを使用する必要があり、これはすべてのファイルを競合として扱うため、手動で修正が必要である。また、`git cherry-pick`が推奨され、これはコミットのパッチを適用することで、変更を正確に反映する。テンプレートリポジトリの変更が子リポジトリに反映されない原因は、gitのマージベースが存在しないためである。テンプレートリポジトリの変更を子リポジトリに引き継ぐには、特別な手順やツールが必要であり、手動で行う必要がある。このため、テンプレートリポジトリの変更を子リポジトリに反映させるには、手動で修正を行う必要があり、これは多くのリポジトリで行われているが、手間がかかるため、多くのリポジトリでテンプレートリポジトリの変更が反映されない。  

一方で、GitHubのテンプレートリポジトリ機能は、リポジトリの初期構成を一括で設定するためのツールとして広く利用されている。テンプレートリポジトリを生成する際、Git LFS（Large File Storage）を含むファイルは含まれないため、大容量ファイルの扱いには注意が必要である。また、テンプレートリポジトリから生成されたリポジトリは、テンプレートとの履歴が関係ないため、プルリクエストやマージができないという制限がある。  

さらに、OpenAPI specを公開しているプロジェクトについての調査では、95.3%のプロジェクトが破壊的変更検出を行っておらず、多くのプロジェクトが互換性ゲートを設けていないことが確認された。ただし、破壊的変更を実施したプロジェクトの中には、変更を明示的に通知しているケースも含まれており、一部のプロジェクトでは変更内容をリリースノートに明記している。この結果は、ツールの導入が必ずしも破壊的変更を防ぐわけではないことを示しており、プロジェクトの運用姿勢が重要であることを示唆している。
