# AIコード生成からAST生成へ、セキュリティリスクの軽減が注目

## 結論

AIコード生成ツールの進化に伴い、セキュリティリスクの軽減を目的とした新たなアプローチとして、抽象構文木（AST）の利用が注目されている。AIが直接コードを生成する代わりにASTを生成することで、コードの検証が構造的に可能となり、セキュリティスキャンや型検査などのツールが効果的に機能する。これにより、AI生成コードの実行時のリスクを大幅に削減し、信頼性の高いシステム設計が実現している。

## テーマ概要

AIコード生成ツールが従来は人間がコードを読み込むことを前提としており、セキュリティリスクが高まっていた。しかし、2026年3月24日にHackerNoonで「ASTはAI生成関数の信頼性を高める」という記事が掲載され、AST（抽象構文木）を用いることでコードの信頼性や安全性が向上していることが注目されている。ASTはコードを構造化された形で表現し、セキュリティスキャンや型検査などのツールが効果的に機能する。また、AIがASTを生成することで、コードの検証が構造的に可能となり、リスクをより正確に評価できる。このため、AI生成コードの実行においてセキュリティリスクを大幅に削減する手法として、ASTの利用が今注目されている。

## 共通して確認できる点

AIコード生成ツールは一般的に人間がコードを読み込むことを前提としており、セキュリティリスクが高まっている。しかし、一部のプロジェクトでは、AIがコードを直接生成するのではなく、抽象構文木（AST）を生成する方法が採用されている。これは、ASTを直接実行することでセキュリティリスクを最小限に抑えることができるためである。ASTはコードを構造化された形で表現し、セキュニティスキャンや型検査などのツールが効果的に機能する。2026年3月24日にHackerNoonで「ASTはAI生成関数の信頼性を高める」という記事が掲載され、その中で、ASTを用いることでAI生成コードの実行時のセキュリティリスクが大幅に削減されることが説明されている。また、ASTを用いることでコードの検証が構造的に可能となり、リスクをより正確に評価できる。

## 深掘り調査で得られた知見

AIコード生成ツールの進化に伴い、セキュリティリスクの軽減を目的とした新たなアプローチとして、AST（抽象構文木）の利用が注目されている。記事1では、AIが直接コードを生成する代わりにASTを生成する方法が紹介されており、その背景には「AIが生成したコードを人間が読むというセキュリティモデルは脆弱である」という認識がある。Hyperlambdaという言語では、ASTを直接実行する仕組みを採用し、コードの実行前に構造的に検証可能にしている。これにより、セキュリティスキャンや型検査などのツールが効果的に機能し、リスクを最小限に抑えることができる。また、ASTを用いることで、コードの検証が構造的に可能となり、リスクの評価がより正確になるというメリットがある。

記事2では、ASTを用いることでAI生成関数の信頼性が高まるとされている。AIが直接コードを生成するのではなく、論理構造をASTとして生成することで、セキュリティや予測性が向上する。特に、AIが生成したコードを実行する際には、そのコードがシステムにどのような影響を与えるかを事前に検証できるため、信頼性が高まっている。また、ASTは構造化されたデータであり、ツールによる解析が容易であり、セキュリティスキャンや型検査などのプロセスが効率的に行える。このような理由から、ASTの利用はAI生成コードの信頼性向上に大きく貢献している。

さらに、記事3や記事4では、ASTを用いたプログラミング言語の実装が紹介されている。lumen-langはPure Pythonで実装され、Lexer、Pratt Parser、バイトコードコンパイラ、スタックベースの仮想マシンを含むプログラミング言語として設計されており、ASTを構造化された形式で扱うことで、コンパイラやツールが効果的に動作する。nyx-langはC99で実装され、手書きのLexer、単一パスのPrattパーサー、スタックベースのバイトコード仮想マシン、マーキングスイープのガベージコレクターを含む。これらの言語は、パース理論、データ構造、システムレベルのメモリ管理を実装しており、小規模なプロジェクトでこれらを完全に理解できるように設計されている。このような実装は、ASTを用いたプログラミング言語の開発における実践的な例として挙げられる。

また、記事5では、Puduという静的型付けの表現志向のプログラミング言語が紹介されており、2026年に設計され、現在はバージョン0.1.2のプレリリース版である。PuduはGitHubで開発されており、コンパイラ、標準ライブラリ、ツールが含まれており、Language Server Protocolをサポートしている。このような言語の開発は、ASTを用いたプログラミング言語の進化の一環として注目されている。

## 不確実な点・追加確認が必要な点

記事間では、AI生成コードのセキュリティ向上に向けたASTの利用が共通のテーマとして取り上げられているが、具体的な実装や背景にはいくつかの違いや不確実な点が存在する。例えば、記事1ではHyperlambdaという言語がASTを直接実行可能な構造として紹介されており、セキュリティリスクを最小限に抑える仕組みを説明している。一方、記事2ではASTがAI生成関数の信頼性を高める理由として、構造化された表現により検証が容易になるという点を強調している。しかし、どの記事にも具体的な実装時期や開発者の所属情報は記載されておらず、時系列的な背景を明確にするには追加の情報が必要である。また、記事3や記事4では、Pure PythonやC99をベースにしたプログラミング言語の開発が紹介されており、ASTの利用が言語設計の一部として採用されていることが示されているが、これらがAI生成コードのセキュリティ向上に直接関係しているかは明確でない。さらに、記事5ではPuduという言語の設計思想が述べられているが、そのAST利用の詳細については記載がされていない。そのため、ASTの利用がAI生成コードのセキュリティ向上にどのように寄与しているか、あるいはどの程度の実践が行われているかについては、さらなる調査や情報収集が必要である。
