# WordPressパフォーマンス改善の実践ガイド

## 結論

WordPressのパフォーマンス改善において、テーマやプラグインの設定変更が核心的な役割を果たすことが明確となりました。特に、スクリプトの肥大化やWebフォントの配信方法、jQueryとjquery-migrateの非同期読み込みといったフロントエンドの最適化手順は、パフォーマンス向上に不可欠です。また、WordPress 7.1のクライアントサイドメディア処理は、サーバー負荷を軽減する効果はありますが、画像の最適化には専用プラグインの利用が依然として必要です。

## テーマ概要

WordPressのパフォーマンス最適化は、近年特に注目されているトピックです。特に、WordPress 7.1のリリースにより、クライアントサイドでのメディア処理が導入され、画像の圧縮やサムネイル生成がブラウザで行われるようになりました。これにより、サーバー側のPHPメモリ制限やアップロードタイムアウトといった問題が解消され、特に共有ホスティング環境での利用が可能となりました。しかし、この機能は画像の最適化とは異なるものであり、ページ速度を重視する場合、専用の画像最適化プラグインの利用が依然として必要です。また、この変更により、既存のメディアライブラリの画像は変更されず、新しいアップロードされた画像のみが処理されます。このような背景から、実際の現場でのWordPressパフォーマンス改善の実践的なアプローチが求められており、本テーマはその具体的な手順や効果的な最適化方法を解説しています。

## 深掘り調査で得られた知見

WordPress 7.1 では、クライアントサイドでのメディア処理が導入され、画像の圧縮やサムネイル生成がブラウザで行われるようになった。これは、サーバー側での PHP メモリ制限やアップロードタイムアウトといった問題を解消する目的で行われた。特に、共有ホスティング環境ではこの変更が有効で、HEIC、AVIF、HDR 画像の自動デコードやアップロード中の接続中断時のリトライ機能が追加された。ただし、この処理は既存のメディアライブラリにある画像には影響を与えず、新規アップロードされた画像のみがこのパイプラインを通る。また、クライアントサイド処理は Chromium ベースのブラウザ（Chrome や Edge 137+）でのみ動作し、Firefox や Safari ではサーバー側の処理が行われる。JPEG の圧縮品質は固定で 82 に設定されており、画像の内容に応じた最適化は行われない。そのため、画像の最適化には専用のプラグインが依然として必要であり、WordPress 7.1 は画像の圧縮やフォーマット変換の機能を提供しているが、画像の品質を最大限に高めるには、画像最適化プラグインの使用が推奨される。

## 不確実な点・追加確認が必要な点

WordPress 7.1 では、クライアントサイドでのメディア処理が導入され、画像の圧縮やサムネイル生成がブラウザで行われるようになった。これは、サーバー側の PHP メモリ制限やアップロードタイムアウトの問題を解消するための改善であり、特に共有ホスティング環境での利用が期待されている。ただし、この機能は画像の最適化とは異なるものであり、画像の品質を向上させるには専用の最適化プラグインが必要である。例えば、ShortPixel などのプラグインは、SSIM（Structural Similarity Index）などの技術を用いて、視覚的に区別できない最小のファイルサイズに最適化する。一方で、WordPress 7.1 は JPEG の圧縮品質を固定で 82 に設定しており、画像ごとの最適化は行われない。また、既存のメディアライブラリにある画像は、この新しい処理パイプラインに影響を受けず、そのままの状態で残る。さらに、クライアントサイド処理は Chromium ベースのブラウザ（Chrome や Edge 137+）でのみ動作し、Firefox や Safari ではサーバーサイド処理が実行されるため、すべてのユーザーにとって結果が同じとは限らない。そのため、パフォーマンス向上だけでなく、画像品質やフォーマットの選択肢を提供するには、専用の画像最適化プラグインの利用が依然として必要である。
