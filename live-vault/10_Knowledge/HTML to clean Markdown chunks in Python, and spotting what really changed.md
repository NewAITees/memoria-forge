# HTMLをクリーンなMarkdownに変換し変更点を検出する技術

## 結論

Python標準ライブラリのみを用いてHTMLをクリーンなMarkdownに変換し、変更点を検出する技術は、ウェブページのコンテンツを効率的に管理・検索するための実用的な方法として確立されている。このプロセスでは、HTMLの構造を解析し、不要な要素を除外することで主なコンテンツを抽出し、SHA-256ハッシュを用いて文書の同一性を確認する。また、リンク先の除去や空白の除去をしたハッシュを比較することで、意味的な変更を検出する仕組みが採用されており、検索インデックスやRAGパイプラインでの利用に適している。

## テーマ概要

HTMLをクリーンなMarkdownに変換し、変更点を特定する技術が注目されている。このテーマでは、Python標準ライブラリのみを用いて、ウェブページをMarkdown形式に変換する方法が紹介されている。変換プロセスでは、HTMLの要素を抽出し、不要な要素（スクリプト、スタイル、ナビゲーションなど）を除外することで、主なコンテンツのみを抽出する。さらに、変更点を検出するために、テキストのハッシュ値を比較する手法が採用されている。具体的には、バイト単位での同一性を確認するハッシュと、リンク先の除去や空白の除去をした後のハッシュを用いることで、コンテンツの意味的な変更を検出する。このような技術は、検索インデックスやリトリーバル拡張生成（RAG）パイプラインなど、コンテンツの更新を追跡する必要がある場面で重要となる。また、この技術は、LLM（大規模言語モデル）が理解しやすい形式に変換することを目的としており、情報の整理と検索効率の向上を図る。このような背景から、HTMLからクリーンなMarkdownへの変換と変更点の検出は、現在の技術開発において注目されている。

## 共通して確認できる点

Pythonを用いてHTMLをクリーンなMarkdownに変換し、変更点を特定する方法について、複数の記事で共通して確認できる事実があります。HTMLをMarkdownに変換する際には、`html.parser`などの標準ライブラリを活用し、`<main>`、`<article>`、`role="main"`を持つ要素、および`<body>`内の特定の要素（スクリプト、スタイル、ナビゲーション、フォームなど）を除外することで、主なコンテンツのみを抽出します。変換プロセスでは、`<br>`や`<img>`などの空要素はスタックにプッシュされず、終了タグは最近のオープン要素を閉じる仕組みとなっています。リンクは`urljoin`で絶対URLに変換され、同じページ内のアンカーはリンクのテキストのみを保持します。また、`render()`関数はノードの子要素を処理し、テキストとインライン要素を「ラン」に集約し、ブロック要素が出現するまでパラグラフとして出力します。テーブルはパイプテーブルに変換され、セル内のパイプはエスケープされる仕様となっています。さらに、`docs.python.org/robots.txt`で許可されている`/3.13/`と`/3.14/`のドキュメントを用いることで、変更点を特定するための比較対象として利用されています。

## 深掘り調査で得られた知見

Pythonを用いたHTMLからクリーンなMarkdownへの変換プロセスにおいて、変更点を特定するための技術的工夫が注目されている。具体的には、各セクションごとにSHA-256ハッシュと、リンク先を除去し空白を除去したハッシュを生成することで、文書の内容が本当に変化したかを判定する仕組みが実装されている。このアプローチは、検索インデックスやRAG（Retrieval-Augmented Generation）パイプラインへの投入時に、変更が発生したセクションのみを再埋め込むことで、パフォーマンス向上を図る目的がある。  

HTMLのパースには`html.parser`が使用され、イベントベースの処理により、`<main>`、`<article>`、`role="main"`を持つ要素、および`<body>`内のスクリプト、スタイル、ナビゲーション、フォームなどの要素を除外する。このような処理により、ノイズを除去し、意味のある構造を保持したMarkdown出力が得られる。  

また、`html2text`や`markdownify`などのライブラリは、HTMLからMarkdownへの変換を担うが、それぞれの特徴や用途に応じて選択される。例えば、`html.parser`はHTML5パーサーではなく、特定のルールを適用しない簡易なパーサーであるため、ウェルフォーマットされたドキュメントには十分だが、雑なHTMLには`html5lib`や`lxml`が推奨される。  

さらに、リンクの処理では`urljoin`を用いて絶対URLに変換し、同じページ内のアンカーはテキストのみを保持することで、外部リンクの無効化を防ぐ。テーブルはパイプテーブルに変換され、セル内のパイプはエスケープされる。また、`<dt>`要素は平文として扱われ、Sphinxの出力では関数シグネチャを保持し、`*`などの特殊文字はMarkdownの強調を破壊しないように処理される。  

このような技術的工夫は、LLM（大規模言語モデル）が理解しやすい文書構造を生成するための重要な要素であり、特にドキュメンテーションやウェブコンテンツの構造化に有効である。また、Codename OneがJavadocをHugoと統合する取り組みも、ドキュメンテーションの統一性と柔軟性を追求する動きの一例として注目されている。
