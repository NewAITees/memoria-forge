# Rust標準ライブラリのみで実装したクラッシュセーフなキー値ストア

## 結論

Rustの標準ライブラリのみを用いて構築されたStoneKVは、クラッシュセーフなキー値ストアの実現を目指したプロジェクトであり、その設計では`Store::set()`や`Store::delete()`の動作を明確に定義し、`File::sync_all()`の完了を保証することでデータの永続性を実現している。この実装はプロセスクラッシュに対する保証を提供しているが、電源喪失などの状況には対応していないため、実際の運用ではさらなる検討が必要である。

## テーマ概要

Rustの標準ライブラリのみを用いて、クラッシュ安全なキー値ストアを構築する試みが注目されている。このテーマは、765,846Writes/SecondWas a Lieというタイトルで、開発者が自身の実装を通じて「クラッシュ安全」という主張がどれだけ現実的かを検証した経験を共有している。このプロジェクトは、ゼロ依存のハッカソンのトラックDとして提出され、データの永続性を保証するという厳しい要件を満たすことが求められた。開発者は、単に「クラッシュ安全」というキャッチコピーを掲げることではなく、具体的な条件を定義し、それを実装・テストを通じて検証する必要性を強調している。この背景には、Rustの安全性とパフォーマンスの両立を目指す開発者の意欲があり、特にクラッシュ時のデータ整合性を保証する技術的な課題への取り組みが注目されている。

## 共通して確認できる点

Rustの標準ライブラリのみを使用して構築された、クラッシュセーフなキー値ストレージであるStoneKVの開発が報告されている。このプロジェクトは、ゼロ依存のハッカソンのトラックDで行われ、耐久性（Durability）が評価の中心であった。StoneKVは、`Store::set()`や`Store::delete()`が`Ok(())`を返すことで、データがWAL（Write-Ahead Log）に追加され、`File::sync_all()`が完了したことを保証している。再起動時に不完全な最終レコードが検出され、有効なプレフィックスが再現され、無効なテールが物理的に切り捨てられる。このプロセスでクラッシュセーフ性が達成されるが、電源の突然の切断やストレージコントローラーの挙動についてはカバーしていない。また、開発者は、クラッシュセーフ性を達成するためには厳格なテストと設計が求められることを強調している。一方、raioというプロジェクトは、Pixをインスピレーションとしており、Rustで構築されたオープンソースのインスタントペイメントの基盤である。raioは、相互運用性を重視し、単一の中央銀行や市場に依存せず、複数の通貨をサポートし、QRコードによる支払いを実現している。raioは、IOフリーの設計を採用し、決定論的で fuzzable であることを目指しており、カスタムのプロバイダートレイトシステムを採用して新しいPSPの追加が容易にされている。

## 記事ごとの差分・視点の違い

記事「765,846 Writes/Second Was a Lie: Building a Crash-Safe Key-Value Store With Only Rust's Standard Library」では、ゼロ依存のキーバリューストアであるStoneKVの開発過程と、クラッシュセーフな性質を保証するための設計哲学が詳しく説明されている。著者は、単に「クラッシュセーフ」というキャッチコピーを掲げることではなく、具体的な動作仕様を明確にし、その仕様をテストによって検証する必要性を強調している。また、開発中に遭遇した課題や、ベンチマーク結果の誤解など、実際の開発における困難な点も述べている。一方で、記事「I'm building an open-source, Pix-inspired instant-payment foundation in Rust」では、Rustを用いたインスタントペイメントの基盤であるraioの設計と、その相互運用性を重視したアーキテクチャが中心となる。raioは、Pixをインスピレーションとしており、QRコードによる支払い、24/7決済、アリアスベースの支払いキーなどを含む機能を備え、複数の通貨をサポートしている。この記事では、raioが単なる決済手段ではなく、他のネットワークや市場に組み込まれるための「信頼の根幹」を提供することを目的としている点が強調されている。また、raioのマーケティングサイトや、技術的な実装の詳細についても触れられており、オープンソースコミュニティへの貢献を目的とした設計思想が見られる。

## 深掘り調査で得られた知見

記事1では、StoneKVというRustで構築されたクラッシュセーフなキー値ストアの開発が紹介されている。このプロジェクトはゼロ依存性ハッカソンのトラックDに応募したもので、主な目標は耐久性（durability）の実現である。つまり、プロセスが中断された後でもデータが正しく復元されることを保証する。作者は、耐久性を保証するためにはテストによる検証が不可欠であると強調し、単に「クラッシュセーフ」という言葉を掲げることで満足してはいけないと述べている。

StoneKVの設計では、`Store::set()`または`Store::delete()`が`Ok(())`を返すと、書き込みが WAL（Write-Ahead Log）に追加され、`File::sync_all()`が完了したと明示的に保証している。再起動時に不完全な最終レコードが検出され、有効な前半部が再現され、無効な後半部は物理的に切り捨てられる。これはプロセスクラッシュに対する保証であり、突然の電源喪失やストレージコントローラーの挙動など、`File::sync_all()`の保証を超えた状況には対応しない。

開発プロセスでは、基本的な機能（キーの設定、取得、削除）の実装が1週間で完了したが、プロセスが中断される際の挙動の処理が主要な課題となった。この過程で3つの予想外の問題に直面した。1つ目は、安全チェックが暗黙に矛盾していること、2つ目は削除されたキーが技術的に復活する可能性があること、3つ目はベンチマークの数値が見事に見えながら実際にはほぼ意味を持たないことだった。作者は、クラッシュセーフなキー値ストアの構築は単純ではなく、厳密なテストと設計が必須であると結論付けている。
