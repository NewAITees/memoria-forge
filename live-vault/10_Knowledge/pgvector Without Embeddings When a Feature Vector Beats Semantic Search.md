# pgvector Without Embeddings: 特徴ベクトルがセマンティック検索を越える

## 結論

pgvectorは、埋め込みモデルから得られたベクトルだけでなく、手動で計算された特徴ベクトルにも対応し、構造化データの類似性検索において特徴ベクトルの利用が有効であることを明確に示しています。一方で、Amazon DynamoDBではベクトル検索機能が実装され、既存のテーブルに semantic search を追加可能となり、ベクトル埋め込みを操作データとともに保存できるようになり、運用上の負荷を軽減しています。これらの技術は、セマンティック検索や推薦エンジン、RAGパイプラインなど、さまざまな用途に応じて活用可能であり、特に構造化データの処理において特徴ベクトルの活用が注目されています。

## テーマ概要

pgvectorはPostgreSQLにおいてベクトル類似性検索を実現するための拡張機能であり、埋め込みモデルから得られるベクトルだけでなく、手動で計算された特徴ベクトルにも対応しています。この特性により、pgvectorはセマンティック検索に特化したものではなく、あらゆる種類のベクトルデータを処理可能な汎用的なツールとして位置づけられています。特に、構造化データに対して意味的な類似性を求める場合、特徴ベクトルがより適切な選択肢となることがあります。一方、Amazon DynamoDBでは、ベクトル検索機能が実装され、既存のテーブルにベクトルインデックスを追加することで、セマンティック検索を実現するようになりました。この機能は、データベースにベクトルを直接保存し、自然言語での検索を可能にすることで、運用上の負荷を軽減し、スケーラビリティを向上させています。このような背景から、「pgvector Without Embeddings: When a Feature Vector Beats Semantic Search」というテーマは、ベクトル検索技術の進化と、特徴ベクトルの活用可能性に注目が集まっているため、現在の技術動向において重要性を増しています。

## 共通して確認できる点

pgvectorはPostgreSQLにベクトル型(vector(N))、距離演算子(<->, <=>, <#>), そして近似最近隣検索インデックス(HNSW, IVFFlat)を追加することで、ベクトル間の類似性検索を可能にします。pgvectorはベクトルの出所を問わず、類似性検索を実行します。つまり、埋め込みモデルからのベクトルでも、手動で計算された特徴ベクトルでも使用可能です。埋め込みベクトルは、非構造化データの意味をモデルが学習した表現であり、特徴ベクトルは構造化データの明示的な特徴を計算したものです。pgvectorは埋め込みベクトルだけでなく、手動で計算された特徴ベクトルにも対応しており、汎用性が高くなっています。

一方、Amazon DynamoDBは2026年8月5日に一般利用を開始したベクトル検索機能により、既存のテーブルに_semantic search_を追加できるようになりました。この機能により、ベクトル埋め込みを操作データとともに保存し、直接類似性検索を実行できるようになり、別途ベクトルデータベースを必要としなくなりました。DynamoDBのベクトル検索は、単一桁のミリ秒 latency で99%以上のrecallを実現し、スケーラビリティが確保されています。また、サーバーのプロビジョニングや管理が不要で、サーバーレスのインフラストラクチャを活用しています。

これらの技術は、セマンティック検索や推薦エンジン、RAGパイプラインなど、さまざまな用途に適用可能であり、特に構造化データの類似性検索において、特徴ベクトルの利用が有効であることが示されています。

## 深掘り調査で得られた知見

pgvectorはPostgreSQLにおいて、ベクトル型(vector(N))、距離演算子(<->, <=>, <#>), および近似最近隣検索インデックス(HNSW, IVFFlat)を提供することで、ベクトル間の類似性検索を実現しています。この機能は、埋め込みモデルから得られたベクトルだけでなく、手動で計算された特徴ベクトルにも対応しており、汎用性が高く、さまざまな用途に応じて利用可能です。例えば、セマンティック検索や推薦エンジン、RAGパイプラインなど、構造化データを扱う場面で特に効果を発揮します。

特徴ベクトルは、ユーザーが明示的に設計し、各次元の意味を理解できるベクトルであり、構造化データの類似性検索において優れた性能を示します。一方、埋め込みベクトルは、非構造化データの意味をモデルが学習した表現であり、特徴の可解釈性が低く、複雑な処理が求められる場合があります。pgvectorは、これらのベクトルを問わず、類似性検索を実行するための柔軟な設計を提供しています。

また、Amazon DynamoDBにおいても、ベクトル検索機能が追加され、既存のテーブルに semantic search を導入することが可能となりました。この機能により、ベクトル埋め込みを操作データと併せて保存し、自然言語での検索が可能となりました。DynamoDBのベクトル検索は、リアルタイムでの検索をサポートし、単一桁のミリ秒 latency で99%以上のrecallを達成しています。また、サーバーレスのアーキテクチャにより、インフラの管理やメンテナンスが不要となり、スケーラビリティが確保されています。この機能は、推薦エンジンやパーソナライズされた体験の実装に特に有用です。

## 不確実な点・追加確認が必要な点

pgvectorは、埋め込みベクトルだけでなく、手動で計算された特徴ベクトルにも対応しており、汎用性が高くなっています。しかし、各記事の内容にはいくつかの食い違いや、資料からは断定できない点があります。例えば、記事1では、pgvectorがベクトル検索を行う際、埋め込みモデルからのベクトルだけでなく、手動で計算された特徴ベクトルも使用可能であると述べています。一方で、記事2では、pgvectorがベクトル検索を実行する際、埋め込みベクトルを前提としており、特徴ベクトルの使用については明記されていません。また、記事4では、DynamoDBがベクトル検索をサポートし、埋め込みベクトルを生成してテーブルに保存する方法が説明されていますが、特徴ベクトルの使用については言及されていません。これらの違いは、各記事の目的や対象読者層に起因する可能性があります。また、pgvectorのパフォーマンスやインデックス構築方法に関する情報は、資料によって異なり、一貫性がありません。例えば、記事1では、次元数が多いと処理負荷が増加する可能性があると述べていますが、記事2では、次元数とパフォーマンスの関係に関する情報が矛盾していると指摘しています。これらの点は、今後の調査や実験によって確認する必要があります。
