# 暗号化ファイルストレージとP2Pによる共有ルール制御

## 結論

暗号化技術とP2P通信の導入により、ユーザーが自身のデータを制御し、共有ルールを柔軟に設定できるファイル共有サービスが注目されている。特に、クライアントサイドの暗号化や、リンクごとのルール設定、データの完全削除を保証する仕組みは、プライバシーやセキュリティを重視するユーザーにとって重要な選択肢として位置づけられている。

## テーマ概要

暗号化されたファイルストレージや共有リンクによるルール設定、P2P通信の利用が注目されている背景には、ユーザーがデータの制御権を確保したいというニーズがある。近年、クラウドストレージサービスの利用が増加している一方で、データのプライバシーやセキュリティへの懸念も高まっている。特に、ファイル共有サービスにおいては、アップロードしたファイルがどのように保存され、誰にアクセスできるかが重要な課題となる。そのため、ユーザーが自身で暗号化を施し、共有リンクのルールを設定できるサービスや、P2P通信を活用した非中央集権的なファイル共有が求められている。このような背景から、暗号化技術を活用したファイルストレージや共有リンクの管理、P2P通信を組み合わせたソリューションが注目されている。

## 共通して確認できる点

複数の記事から共通して確認できた事実として、暗号化されたファイルストレージや共有リンクのルール設定、P2P通信の導入が注目されている。特に、AES-256-GCMによるクライアントサイドの暗号化が採用されている例が見られ、アップロードされたファイルはブラウザで暗号化され、サーバー側で生成された鍵がメールで送信され、その後は保存されない。これにより、メールを失えばファイルも失われる仕組みとなっており、復元手段は存在しない。また、共有リンクは個別に設定可能で、パスワード、ダウンロード制限、有効期限などのルールを設定でき、リンクごとに独立して取り消すことが可能。さらに、WebRTCによるP2P通信が提供されている例もあり、アップロードやサイズ制限、データ保存が一切行われない。このような設計は、ユーザーがデータの制御を保つことを目的としており、多くのサービスが無料で利用可能であるが、一部のサービスでは有料プランも提供されている。

## 記事ごとの差分・視点の違い

記事「Encryptedfilestorage,sharelinksyouactuallysettheruleson,or...」では、クライアントサイドの暗号化とサーバー側での鍵管理の仕組みが強調されており、ファイルの共有リンクでルールを個別に設定できる点が特徴である。また、WebRTCによるP2P通信を採用し、アップロードや保存が一切行われない点も重要な視点として提示されている。一方、「Why I built an open source alternative to WeTransfer」では、WeTransferの利用経験と、その変更された利用規約への不満から、自らのデータを制御できるオープンソースの代替サービス「Campsend」を開発した経緯が詳しく説明されている。この記事では、データの所有権やプライバシーの重要性が強調されており、自前のS3互換ストレージを接続することで、データを自分で管理できる点が特徴である。また、「GitHub - obakeng-develops/campsend: Open source alternative ...」では、Campsendの技術的な実装と、自前サーバーでの運用が可能である点が中心となっており、RubyとSQLiteを用いた簡易な構成が紹介されている。一方、「IBuiltanEncryptedTextSharingToolWithZeronpm...」では、ゼロnpm依存関係を活用した暗号化されたテキスト共有ツールの設計が焦点となり、ブラウザとサーバーの通信における暗号化の仕組みが詳細に説明されている。さらに、リアルタイム同期や言語の構文強調、音声ノートの暗号化などの機能が特徴として挙げられている。これらは、暗号化されたファイル共有の実装方法や、ユーザーがデータを制御できる仕組みの違いを示す重要な視点である。

## 深掘り調査で得られた知見

深掘り調査により、暗号化されたファイルストレージや共有リンクでのルール設定、P2P通信の導入など、ファイル共有サービスの新たなトレンドが明確に浮かび上がった。sharenod.comはAES-256-GCMによるクライアントサイド暗号化を採用し、アップロードされたファイルはブラウザで暗号化され、サーバー側で一時的に生成された鍵がメールで送信され、その後は保存されない。これにより、メールを失うとファイルも永久に失われる仕組みとなっており、復元手段は存在しない。また、共有リンクは個別に設定可能で、パスワード、ダウンロード制限、有効期限などを設定でき、リンクごとに独立して取り消すことが可能。さらに、WebRTCによるP2P通信を提供し、アップロードやサイズ制限、データ保存が一切行われない。Backblaze B2をストレージとして使用し、Kubernetesを採用した小規模なVPSにデプロイされている。  

一方、Campsendはオープンソースで、自前サーバーに設置可能なファイル共有サービスであり、WeTransferのシンプルな送信体験を再現することを目的としている。このサービスは、S3互換のストレージバケットにファイルを保存し、ユーザーが自分のインフラストラクチャを制御できるようにする。Rails 8とSQLiteを採用し、Ruby 3.3.4とSQLite 3を必要とする。また、WeTransferの利用規約変更により、データ所有権やプライバシーに関する懸念が生じたことから、Campsendが開発された背景も確認できた。  

また、暗号化されたテキスト共有ツールの開発事例も確認され、ゼロnpm依存関係を活用した設計が採用されている。このツールでは、ブラウザがURLフラグメントをサーバーに送信しないという仕組みにより、サーバーがメッセージを読むことができない。秘密鍵はクライアントにのみ存在し、サーバーは取得できない。この設計により、端到端の暗号化が実現されており、リアルタイム同期や構文強調、暗号化された音声ノート、5MBまでのファイル共有、パスワード保護されたルームなどの機能を備えている。このツールはオープンソースであり、プルリクエストを受け入れており、技術的な改善点についてもコメントを募集している。  

これらのサービスは無料で利用可能であり、ユーザーがデータを制御し、共有ルールを設定できる点が特徴である。暗号化技術やP2P通信の導入により、ファイル共有のセキュリティとプライバシーが強化されており、今後のファイル共有サービスの動向として注目される。

## 不確実な点・追加確認が必要な点

記事間では、暗号化されたファイルストレージや共有リンクのルール設定、P2P通信の導入などに関する技術的な実装や設計思想の違いが確認されている。例えば、sharenod.comではAES-256-GCMによるクライアントサイドの暗号化が採用されており、生成された鍵はメールで送信され、サーバー側では保存されない。これにより、メールを失うとファイルは完全に消失するという仕組みが採用されている。一方、Campsendはオープンソースで、S3互換のストレージバケットにファイルを保存し、ユーザー自身がデータを制御できるように設計されている。また、ファイルの共有リンクは期限切れやパスワード保護が可能で、リンクごとに独立して取り消すことができる。 

一方で、IBuiltanEncryptedTextSharingToolWithZeronpm...の記事では、ブラウザがURLフラグメントをサーバーに送信しないという仕組みを活用し、秘密鍵がクライアントにのみ存在するように設計されている。これにより、サーバーはメッセージを数学的に読むことができない。このような設計は、暗号化されたテキストや音声ノートの共有に特化しており、ファイルサイズの制限（最大5MB）やリアルタイム同期、言語の構文強調など、用途に応じた機能が備わっている。 

また、記事間では、無料での利用が可能なサービスが複数存在する一方で、Proton DriveやCampsendは有料プランも提供している点が確認されている。ただし、Proton Driveは端到端の暗号化を謳っているものの、すべてのファイルやメタデータを暗号化しているかは明記されていない。一方、sharenod.comではファイルの削除後、サーバーに残らないことを強調しているが、すべてのデータが完全に削除される保証はされていない。 

このような情報から、各サービスの設計思想や機能の違いが明確になっており、ユーザーが自身のニーズに応じて選ぶ際の参考となる。ただし、すべてのサービスが完全なデータ保護を提供しているかは、明確な情報が不足しているため、断定することはできない。
