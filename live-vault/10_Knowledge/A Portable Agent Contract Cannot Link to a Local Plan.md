# ポータブルエージェント契約はローカルプランとリンクできない

## 結論

A Portable Agent Contract Cannot Link to a Local Plan というテーマは、AIアーキテクチャにおけるガバナンスの移行と、コード生成ツールのポートアビリティに関する重要な課題を浮き彫りにしています。特に、エージェント契約がローカルな計画や設定に依存してしまうと、ポータブルな契約としての機能を失う可能性があり、企業規模でのAIガバナンスの分散化が進む中で、この課題はより一層重要になっています。そのため、ローカルな設定に依存しない、機械可読なポータブルなエージェント契約の設計が求められています。

## テーマ概要

A Portable Agent Contract Cannot Link to a Local Plan というテーマは、AIアシスタントやエージェント技術におけるガバナンスと運用の課題を掘り下げた議論を指します。このテーマは、エージェント契約がローカルな計画や設定に依存してしまうと、ポート可能な契約としての機能を失う可能性があるという点に注目しています。特に、企業環境でのAIガバナンスが分散化し、プラットフォーム中心の管理からエージェント中心のモデルへ移行する中で、エージェントの動作や制御を一貫して管理するためには、ローカルな設定に依存しない Portable Agent Contract の設計が求められているのです。また、OpenAIのCursorモデルの利用停止や、AI生成コードの品質管理におけるリントツールの課題など、技術的・運用的な変化がこのテーマを今注目させています。

## 共通して確認できる点

A Portable Agent Contract Cannot Link to a Local Planというテーマは、AIアーキテクチャにおけるガバナンスの移行と、コード生成ツールのポートアビリティに関する課題を反映しています。記事1では、企業AIガバナンスがプラットフォーム中心からエージェント中心へ移行していることが述べられており、エージェントの展開が拡大するにつれ、ガバナンスが分散する問題が指摘されています。その解決策として、宣言的なエージェント契約（smart agreements）を導入し、サイドカープロキシを通じて実行する方法が提案されています。この契約は、エージェントのモデル、ツール、メモリ、評価、可観測性、セキュリティ制約、エスカレーションルールを含む機械可読の仕様を定義するものであり、プラットフォームに依存せず、エージェントの運用境界を明確にする必要があります。

記事2では、OpenAIがCursorモデルへのアクセスを停止する予定であることが示されており、その影響として、コード生成エージェントが使用するモデルプロバイダーへの依存がソフトウェアサプライチェーンに組み込まれることを指摘しています。この変更は、開発チームにとって重要な依存関係の再評価を必要とし、その影響がコードの実行やポリシー承認に現れる可能性があります。そのため、チームはモデルプロバイダーの変更に備えて、インベントリ作成、テスト、ガバナンスの再評価を行う必要があります。

記事4では、AI生成コードのリント設定において、エラーの返却チェックとセキュリティパターンの検出が特に重要であると述べられており、Go言語ではこれらのルールが特に効果的であるとされています。また、AI生成コードは、チームのコードベースのパターンを学ばないため、特定のチームのコンベンションに従わないコードを生成することがあり、その結果、チームのコンベンションの違反や構造的なエラーが生じることがあります。そのため、AI生成コードのレビューでは、チームのコンベンションを理解し、コードの構造をチェックする必要があります。

## 深掘り調査で得られた知見

A Portable Agent Contract Cannot Link to a Local Plan というテーマは、AIアーキテクチャにおけるガバナンスの移行と、コード生成ツールのポートアビリティに関する重要な課題を浮き彫りにしています。調査結果によると、企業AIガバナンスはプラットフォーム中心からエージェント中心へと移行しており、この変化はエージェントのデプロイが拡大するにつれて、ガバナンスの分断を引き起こす問題を解決する必要が生じています。その対応策として、宣言的エージェント契約（declarative agent contract）が提案されており、これはエージェントのモデル、ツール、メモリ、評価、可観測性、セキュリティ制約、エスカレーションルールなどを機械可読の形式で定義するもので、プラットフォームに依存しないポータブルなガバナンスを実現します。この契約は、リポジトリの外部に配置されるべきであり、ローカルなプランとリンクすることはできません。その理由は、ローカルなプランがエージェントの実行環境に依存し、ポータビリティを損なうためです。

また、OpenAIがCursorモデルへのアクセスを2026年11月12日に停止する予定であることが明らかになり、これによりAIコード生成ツールの継続的な運用が脅かされる可能性があります。CursorはSpaceXに買収され、その結果、OpenAIモデルへのアクセスが制限されるため、ソフトウェアチームは今後の数週間をかけて、現行のワークフローを_inventory_、テストし、ガバナンスを再評価する必要があります。この例は、AIツールの依存関係がソフトウェアサプライチェーンに組み込まれていることを示しており、モデルプロバイダーとの契約変更がコード生成プロセスに重大な影響を及ぼす可能性があることを示しています。

さらに、AI生成コードはローカルに正しいが、リポジトリ全体のコンテキストと矛盾している場合があるため、リントツールはローカルなエラーを検出するだけでなく、リポジトリ全体のコンテキストを考慮するための別のレベルのチェックが必要です。例えば、AI生成コードは未使用のインポート、エラーリターンの無視、セキュリティパターンの欠如などの問題を引き起こす傾向があります。そのため、特定の言語（Python、TypeScript/JavaScript、Go）に特化したリントルールの設定が求められ、IDEレベル、pre-commit hooks、CIレベルで階層的に設置されることが推奨されています。こうした設定により、AI生成コードの品質を保証し、チームのコンベンションに合致したコードの生成を促進します。

## 不確実な点・追加確認が必要な点
