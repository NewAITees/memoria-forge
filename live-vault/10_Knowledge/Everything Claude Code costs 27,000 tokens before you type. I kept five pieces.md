# Everything Claude Codeの初期トークンコストとその影響

## 結論

Everything Claude Code（ECC）の初期トークンコストは27,000トークンで、これは200,000トークンのコンテキストウィンドウの14%に相当し、スキルメタデータ（名前や説明）がセッション開始時に常に読み込まれる仕組みによるものである。このコストはユーザーが実際のコード作業に入る前から発生するため、利用する際には事前にその影響を考慮する必要がある。

## テーマ概要

Everything Claude Code（ECC）は、コード作成支援ツールとして注目されているが、その使用には高いトークンコストがかかることが問題となっている。ECCのインストール時点で、スキルのメタデータ（名前や説明）が27,000トークンのコンテキストを占め、これは200,000トークンのコンテキストウィンドウの14%に相当する。このコストは、ユーザーが実際のコード作業に入る前に発生するため、利用する際には十分な注意が必要である。また、トークンコストは、モデルやプロンプトの種類によって大きく変動するため、正確なコスト見積もりは難しい。このような背景から、ECCのトークンコストに関する情報が注目されており、開発者や利用者はコスト管理の観点からその影響を評価している。

## 共通して確認できる点

Everything Claude Code (ECC) は、コーディング用のツールとスキルを含むリポジトリで、286のスキル、68のエージェント、94のスラッシュコマンド、122のルールファイル、23のハックを提供しています。このリポジトリは25万スターを獲得しており、その人気と広範な使用が示されています。ECCのメタデータのトークンコストは27,000トークンで、20万トークンのコンテキストウィンドウの14%に相当します。スキルのボディは使用時に遅延ロードされるのに対し、スキル名や説明はセッション開始時にコンテキストに読み込まれます。ECCリポジトリのREADMEでは、コンテキストウィンドウを最適化し、その他の情報を永続化するよう推奨していますが、286のスキルを含むため、すべてのユーザーにとって関連性があるわけではありません。また、ECCリポジトリには「AgentShield」というツールが含まれており、エージェント構成を監査する機能を持ち、npmでも利用可能です。このツールは、1つのスキルマーケットプレイスの12%が悪意のあるコードであると主張していますが、これはパッケージの主張であり、独立した検証はされていません。ECCリポジトリのREADMEでは、`.claude/settings.json` の4つの変更が提示されており、モデルコストを60%削減、隠された思考コストを70%削減する可能性があるとされていますが、これはリポジトリ側の数字であり、独立した検証はされていません。

## 深掘り調査で得られた知見

Everything Claude Code (ECC) は、コードの作成や分析に特化したツールを多数収録したリポジトリで、27,000トークンの初期コンテキストを占有する。これは200,000トークンのコンテキストウィンドウの14%に相当し、スキルのメタデータ（名前や説明）はセッション開始時にロードされるが、スキル本体は使用時に遅延ロードされる。この初期コストは、ユーザーが実際にコードを入力する前から発生するため、予算管理において重要な要素となる。

同リポジトリでは、スキルの数が286に達し、その多くはユーザーにとって関連性のないものである可能性がある。そのため、ECCの使用には、必要最小限のスキルのみをインストールする最適化が推奨される。また、リポジトリ内には「AgentShield」というツールが含まれており、エージェントの構成を監査する機能を持つ。このツールは、npmで利用可能で、12%のスキルマーケットプレイスが悪意のあるものであると主張しているが、その情報はリポジトリの更新日（昨日）と矛盾しており、最新の状況とは一致しない。

トークンコストの計算においては、4文字あたり1トークンと推定されているが、トークナイザーの違いにより実際の数値は変化する。また、トークンコストは全体コストの大きな要因となるため、使用前には事前に確認することが必要である。さらに、ECCのREADMEでは、トークンコストを減らすための設定変更が提案されており、モデルコストや隠し思考コストをそれぞれ60%と70%削減する可能性があるとされるが、これはリポジトリ側の主張であり、独立的な検証は行われていない。

## 不確実な点・追加確認が必要な点

Everything Claude Code (ECC) に関する情報では、27,000トークンが初期コンテキストに占有しているという記述が見られる。これは200,000トークンのコンテキストウィンドウの14%に相当する。このトークン数はスキルのメタデータ（名前と説明）がセッション開始時に読み込まれるためのコストとされる。一方で、スキル本体（実際の処理内容）はスキルが使用されるまで読み込まれないため、初期コストには含まれない。ただし、この情報は記事1のみに記載されており、他の記事では具体的なトークン数やコストの詳細が記載されていない。

また、 Claude Token Costs Explained では、トークンコストが単にユーザーが入力したメッセージだけでなく、インストラクション、ツール定義、履歴、ツール結果などが含まれる点が説明されている。さらに、セッションコンテキストの影響で、後続のトークン数が増加する可能性があるとされている。ただし、具体的な数値やコストの計算方法については記載されていない。

記事3では、1つのサービスを分析するのに3.8百万トークンが使用されたと記載されており、これはツール（Graphify）によるコード解析の結果である。しかし、この数値は他の記事では確認されておらず、一時的な測定結果である可能性がある。また、同記事では、トークン数がコストに直結するとは限らず、ツールの使用方法や解析の深さによっても変動する可能性があると述べられている。

記事4では、トークン使用量の推定方法や、AIモデルのコスト構造についてのガイドが提供されているが、具体的な数値やコストの計算例は記載されていない。記事5では、コストモニタリングの誤差や、設定によりコストが変動する可能性が述べられているが、具体的なトークン数やコストの関係性は明示されていない。

これらの記事は、トークンコストの測定方法や、初期コンテキストの影響、ツールの使用によるコストの変動など、いくつかの観点から情報を提供しているが、どの記事も断定的な数値や一貫したコスト計算方法を提示していない。そのため、トークンコストに関する正確な情報は、各記事の記述を比較・検証する必要がある。
