# AIアーキテクトが他人のクラウドでコード実行を避ける理由

## 結論

AI agentsが他人のクラウド環境でコードを実行するリスクは、セキュリティと透明性の観点から深刻な懸念を引き起こしており、実行環境の制御と監査性の確保が不可欠である。そのため、自前のインフラでの実行やネットワークアクセスの制限、実行履歴の記録など、信頼性の高い設計が求められている。

## テーマ概要

AI agentsが他人のクラウド環境でコードを実行することへの懸念が注目されている背景には、AIの能力が急速に進化し、コード実行やデータベースクエリ、API呼び出し、ファイル操作、さらには生産環境へのアクセスまで可能になった点があります。このような機能は開発効率を高める一方で、セキュリティリスクや監査の困難さといった課題も生じています。特に、コード実行環境が外部のクラウドに依存する場合、管理者が実行環境を制御できず、不正アクセスや意図しない操作のリスクが高まります。そのため、多くの開発者や技術者らは、実行環境を自身のインフラに限定し、ネットワークアクセスをデフォルトで無効にして最小限の権限を与えるなど、より安全な設計を求める声が高まっています。このテーマは、AIアーキテクチャにおけるセキュリティと制御のバランスを問うものであり、今後のAIアーキテクチャ設計において重要な議論の一つとなっています。

## 共通して確認できる点

AI agentsの実行環境に関する議論は、複数の記事で共通して取り上げられている。AI agentsはコードの実行、データベースのクエリ、APIの呼び出し、ファイル操作、さらには生産環境インフラとのやり取りまで可能になる一方で、その実行場所が重要となる。特に、他人のクラウド環境で実行されることが懸念されており、セキュリティや監査性の観点から自前のインフラで実行する必要性が強調されている。実行環境の隔離やネットワークアクセスの制限、実行履歴の記録といった対策が提案されており、これらは実行環境の信頼性向上に向けた具体的な取り組みとして挙げられている。また、自前のランタイム環境を構築する動きも見られ、その中にはオープンソースプロジェクトも含まれている。このような議論は、AI agentsの安全性と信頼性を確保するための重要な課題として位置付けられている。

## 記事ごとの差分・視点の違い

記事「Why I don’t want AI agents executing code in someone else’s cloud」では、AIエージェントが他人のクラウド環境でコードを実行するリスクとセキュリティ上の懸念を強調しています。著者は、実行環境の制御が重要であり、ネットワークアクセスをデフォルトで無効にし、必要なときだけ許可するアプローチを提案しています。また、実行履歴の記録と監査の重要性を指摘し、自前で実行環境を構築するプロジェクト「VaultRun」の開発を進めています。一方、記事「I'm building Guren, a fullstack TypeScript framework for the AI-agent era」では、AIエージェントと協働するためのフレームワークの設計とその必要性が強調されており、AIエージェントの出力を検証できる環境を提供することを目的としています。この記事では、フレームワークの設計における型安全や、AIエージェントとの連携を重視しています。また、記事「The AI Coding Team Working Agreement (Template)」では、AIエージェントをチームに導入する際のチームワークの重要性と、チームのルールを明確にする必要性が述べられています。この記事では、チーム内で共有されるルールとその実装が、AIエージェントの動作を制御する上で不可欠であると強調しています。他の記事では、AIとクラウドスキルの統合や、AIエージェントの設計におけるコンテキストエンジニアリングの重要性が論じられていますが、それぞれの記事は、AIエージェントの実行環境やチームでの使用方法、技術的設計の観点から異なる視点で議論しています。

## 深掘り調査で得られた知見

AI agentsのコード実行環境に関する懸念は、開発者コミュニティ内で広く議論されている。特に、AI agentsが他人のクラウド環境でコードを実行するリスクが指摘されており、その安全性と透明性が重要な課題として挙げられている。ある開発者は、AI agentsが実行環境を制御できない場合、ネットワークアクセスやデータベースへの接続など、潜在的なセキュリティリスクが生じる可能性があると述べている。このため、実行環境は自前のインフラで構築し、セッションごとにDockerコンテナで隔離するなどの対策が提案されている。また、実行履歴を署名付きで記録し、詳細な監査が可能となるようにするなどの設計が検討されている。このような動きは、AI agentsの信頼性を高めるための技術的対応の一例であり、今後さらに進化する可能性がある。また、AI agentsを効果的に活用するためのフレームワークの開発も進んでおり、Gurenなどのプロジェクトがその代表例として挙げられる。これらの取り組みは、AI agentsの安全かつ効率的な利用を目的としており、今後の技術革新に大きく影響を与える可能性がある。

## 不確実な点・追加確認が必要な点

記事間では、AIアーキテクチャにおけるセキュリティと運用の枠組みについての議論が展開されているが、具体的な実装や実際の運用状況については明確なデータが提示されていない。例えば、記事1では自前のランタイム環境であるVaultRunの設計思想が述べられているが、その導入実績や運用コスト、セキュリティリスクの具体的な評価は提示されていない。また、記事2で紹介されたGurenフレームワークはAIアーキテクチャとの連携を強調しているが、その実際の導入先や、AIエージェントとの連携における課題については言及されていない。さらに、記事3ではチームでのAIコード作成における作業規約の重要性が述べられているが、その導入効果や、AIエージェントの導入前後のチームダイナミクスの変化についてはデータが不足している。これらの点を踏まえると、AIエージェントの実行環境に関する議論は、技術的な設計思想やフレームワークの特徴に焦点を当てているものの、実際の導入事例や運用状況の詳細は提示されていない。そのため、記事間の整合性や実践的な課題については断定的な結論を導きにくい。
